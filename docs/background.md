# 后台检测 v1

这是 Const-Time 宿主与本 fork 的配套扩展，不是原上游 SDK 的后台能力。使用现有管理请求/响应的头部元数据承载协议，不暴露新的公网路由、不读取 Key 明文。

## 授权与调度

- 只有直接认证的管理员会话管理调用可启动，嵌套 service 调用、System、Admin API Key、公开登录回调不能启动。
- 宿主在每次管理调用的元数据中注入 `x-cpr-background-version: 1`；插件缺少此能力时在 start/resume/step **之前**返回 409。
- 插件对 start/resume 和成功后仍 Ready 的 step 返回一个 `x-cpr-background-next` 响应元数据头；其 UTF-8 JSON 为 `{"id":"任务 ID","path":"api/runs/step","body":"包含同一 ID 的 JSON 字符串"}`。此头只供宿主消费，不是浏览器 HTTP 头。
- 宿主验证目标为该实例已注册的 JSON POST 路由，再以**原发起管理员身份**创建后台链。每一题是新的有界 management RPC / HostClient 作用域；不复用已结束的请求权限。
- 每个实例最多一条链、每条链最多 162 次调用。单题宿主预算 120 秒，插件读流预算 90 秒；重试仍由插件既有总尝试预算约束。后续 id/path/body 不得改变。非 2xx、RPC 错误、没有续调头或改变目标都立即停止，不自动重试。
- 宿主将本管理员的活动任务 ID 放在 `x-cpr-background-active` 请求元数据中。页面每 3 秒只读刷新状态；隐藏时不轮询，不影响后台任务。另一管理员不能通过此头读取原操作者信息。

## 持久化与停止

任务、冻结题目、pending、尝试、结果继续用插件 runs 命名空间 + CAS 持久化。宿主只持有当前进程内的有限调度租约，不额外维护一套检测状态机。

- 暂停/结束：停止发下一题，当前题尽可能完成并保存结果。
- 失败：保存错误并暂停，用户明确继续才重新调度；错误、拒答或不完整回答不计为有效样本。
- 插件停用、卸载、升级、宿主关闭：撤销作用域并等待后台调用退出。
- 宿主重启/响应丢失：**不自动重放**。pending 保留，手动继续时按未知结果消耗一次尝试预算；不会当作免费重试。
- 关闭页面：只停止页面状态轮询，不撤销已经入队的任务。

后台运行解决的是浏览器生命周期，不保证模型一定成功。配套宿主同时修复原管理 RPC 的 30 秒截断；仍可能发生 429、网络中断、90 秒超时、无效输出或评分失败。
